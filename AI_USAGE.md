# Использование AI

В задании я использовала ChatGPT как помощника при разборе ТЗ, проектировании и написании минимального PoC.

## Где использовала

С помощью AI я:

- обсуждала разделение edge и центрального сервиса;
- структурировала CV/ML pipeline;
- проверяла risky cases и требования к offline-режиму;
- готовила черновики документации.

Код я запускала локально в VS Code и проверяла результат сама.

PoC успешно показал два нужных сценария:

```text
happy path → allow → open
risky liveness → manual_review → no open
```

Smoke-test также был запущен локально и прошёл:

```text
1 passed
```

Отдельно я проверила содержимое `poc/audit.jsonl`.

## Что менялось после ответов AI

Я не принимала все предложения автоматически.

В начале AI предлагал уделять больше внимания продуктовой экономике и дополнительным артефактам. После повторной проверки ТЗ я оставила только обязательный набор для ИИ и не стала делать `product.md` и `WORKLOG.md`.

Для PoC предложил конкретные численные пороги quality, liveness и matching. Они подходят только для демонстрации и не имеют статистического обоснования. Поэтому в итоговом решении я явно обозначила их как demo-пороги, а для целевой системы описала выбор по validation set и FAR/FRR.

## Как проверяла безопасность предложений

При просмотре решений AI я отдельно проверяла, чтобы:

- плохой liveness не мог дать `allow`;
- плохое качество не приводило к автоматическому открытию;
- неуверенный match уходил на ручную проверку;
- устаревший offline-кеш не считался автоматически безопасным;
- повторный `event_id` не открывал турникет второй раз;
- в PoC не использовались реальные биометрические данные;
- исходные изображения не предлагалось хранить постоянно без необходимости.

LLM не используется самой системой для `allow / deny`. В рабочем контуре решение остаётся детерминированным и строится на результатах CV/ML, access policy и заданных правилах.
