# Risks and Operations


- Весь путь выполняется на edge: CV/ML inference, поиск по локальному индексу и decision logic. Это уменьшает сетевую задержку и помогает держать `p95 <= 1 сек`.

- На edge кешируются embeddings и access policy. При потере сети работа возможна только пока локальные данные считаются достаточно актуальными. Если актуальность доступа нельзя подтвердить, автоматического `allow` нет.

- Если недоступна обязательная модель, индекс или access policy, система переходит в безопасный fallback: `manual_review` или `deny`.

- `event_id` используется для того чтобы повторный запрос не должен второй раз открыть турникет. Offline audit events сохраняются локально и синхронизируются после восстановления сети.


- Embeddings считаются чувствительными биометрическими данными. Постоянно хранить исходные изображения для работы системы я не планирую. Templates должны храниться с ограниченным доступом.

- На edge должна храниться только та копия данных, которая нужна для работы конкретной системы доступа.

- При увольнении или отзыве доступа изменение должно быстро попасть на edge. Устаревший кеш не должен быть причиной автоматического допуска.

- Низкое качество, сомнительный liveness, неуверенный match и degraded mode не автоматизируются полностью: они уходят на ручную проверку. Сотруднику можно показать общую причину отказа, но не внутренние пороги и не содержимое biometric template.
